# Contributing and local development

Work on `main`; this fork uses a single maintained branch. Read [DESIGN.md](DESIGN.md) before changing rendering, activation, or lifecycle code. Use [ERRORS.md](ERRORS.md) to collect a reproducible desktop failure.

## Checks

The checks require Node.js 18 or newer, GJS, Python 3.9 or newer, Make, GLib schema tools, zip, and unzip. No npm dependencies are required for the test or syntax scripts.

```sh
npm test
npm run check
glib-compile-schemas --strict --dry-run schemas
```

`npm test` discovers the Node `.mjs` suites and runs the three selected GJS lifecycle/drag suites. Packaging and upgrade checks operate in temporary directories. `npm run check` parses JavaScript; it does not lint or execute the GNOME UI. See [tests/README.md](tests/README.md) for scope and focused commands.

## Build archives

Modern and legacy targets write the same archive filename and recreate `build/`. Copy the first archive before building the second:

```sh
mkdir -p dist
make publish
cp dash2dock-lite@icedman.github.com.zip dist/dash2dock-lite-modern.zip
make publish-g44
cp dash2dock-lite@icedman.github.com.zip dist/dash2dock-lite-legacy.zip
```

The modern archive declares Shell 46–51. The legacy archive declares 42–44 and uses `tools/transpile.py` plus the legacy entry points in `tools/imports_extension.js` and `tools/imports_prefs.js`. Keep new JavaScript compatible with that conversion. Build outputs under `build/`, `dist/`, and ZIP archives are ignored by Git.

`make publish` and `make publish-g44` package local archives; they do not upload a release or install the extension. Plain `make` and `make build` compile the settings schema without installing anything. `make install` builds the modern archive and `make g44` builds the legacy archive, then each calls the official ZIP installer. `make install-zip` installs an already built archive. For upgrades with backups and preference verification, use the helper in [README.md](README.md) instead.

`schemas/gschemas.compiled` is generated and ignored by Git. Both portable archives contain the schema XML; the official installer compiles it for the local system.

## Repository layout and retained sources

File age alone does not indicate whether a source is obsolete. The repository audit checked imports, runtime resource lookups, build recipes, and test discovery before removing unused prototypes and assets.

| Path | Purpose |
| --- | --- |
| Root JavaScript, `apps/`, `effects/` | Dock implementation and drawing helpers. Folder, Trash, and mount launchers are generated by `services.js`; static desktop-file templates are no longer needed. |
| `preferences/`, `ui/`, `themes/` | Current settings bindings, shared preferences UI, icons, support QR, and presets. Both build targets use this UI; the unused `ui/legacy/` snapshots were removed. |
| `tools/transpile.py`, `tools/imports_*.js` | Required JavaScript conversion and entry points for Shell 42–44. |
| `tools/apply_update.py` | Verified upgrades with file/settings backups and rollback. |
| `tests/` | Automated regression suites and their runner; obsolete standalone experiments were removed. |
| `screenshots/`, `.github/images/` | Historical upstream artwork retained with icedman's project attribution. |
| `build/`, `dist/`, ZIP archives | Ignored, reproducible local build outputs. |

`apps/overlay.js` and the color/blur effect sources are retained upstream developer references, covered by focused tests; they are not enabled dock features. Their original adaptation credits remain intact. `lint/` and `.eslintrc.yml` retain upstream lint rules and their license notice as an optional reference; they are not part of the maintained checks. `.prettierrc` remains an optional formatting preset, and `tools/todo.py` extracts the source's `//!` notes with `make todo`.

Keep [icedman's original-project credit and support link](README.md#license-and-attribution), the GPL license, source attribution comments, and support artwork when reorganizing files.

## Desktop development

Use a disposable GNOME session for changes to actors, input, menus, or teardown. Install the matching archive, log out/in to load changed Shell code, and open preferences with:

```sh
gnome-extensions prefs dash2dock-lite@icedman.github.com
```

Watch the Shell journal as described in [ERRORS.md](ERRORS.md). On Wayland, logging out/in is needed to replace already loaded extension modules. Disabling and re-enabling is useful for lifecycle tests and reloading custom configuration, but does not reliably load changed source modules.

Run nested Shell sessions only with flags supported by the installed Shell version. The old host-specific `test-shell*` Make recipes and standalone graphical prototypes have been removed; the automated runner is the supported entry point for repository checks.

## Change and release review

- Add a regression when changing a failure-prone behavior such as actor ownership, activation, timer cleanup, or async ordering. Verify the reported trigger rather than duplicating the implementation in a test.
- Keep single-window toggling, thumbnail selection and free dismissal, retained preview hover, Show Desktop restoration, native modifiers, magnified hit targets, and edge reveal consistent when changing nearby code.
- Check settings keys in `preferences/keys.js` and `schemas/` together. The update helper intentionally refuses schema changes; migrations need separate review.
- Review all relevant Markdown, increment `metadata.json` when preparing a release, and record the final behavior in [CHANGELOG.md](CHANGELOG.md). Extension versions come from `metadata.json`, not the older npm package version.
- Complete [CHECKLIST.md](CHECKLIST.md) and record what was tested. Build success and declared Shell targets do not establish rendering, compatibility, or measured performance.
- Review the diff before committing and use a normal push to `main`. Packaging does not imply that code is installed or published remotely.
